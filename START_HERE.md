# Как пользоваться генератором

Обновление 26 ноября: добавлены разные модели, независимый рост **1,65–1,95 м**,
40% запросов частичного кадра, значительно более разные расстояния/объективы и
отбор pose-кадров с целевой долей **5% реальных перекрытий людьми**. Для обучения
используй `yolo/data.yaml`; полная покадровая запись — `data_all_frames.yaml`.
Проверяй `selection.json`: маленький батч может не содержать достаточно сложных
кадров. Подробности: [разные персонажи и камеры](Docs/CharacterDiversity.md).

## 1. Загрузить анимации

- Удары руками: `Assets/Animations/Attacks/Punch/`.
- Удары ногами: `Assets/Animations/Attacks/Kick/`.
- Idle: `Assets/Animations/Neutral/`.
- Реакции: `Assets/Animations/Reactions/`.
- Блоки и уклонения можно класть в подпапки `Reactions/Block/` и `Reactions/Dodge/`.
- Файлы с понятными именами можно класть в `Assets/Animations/Inbox/`.

Все FBX автоматически настраиваются как Humanoid и добавляются в каталог после
импорта. Категория определяется по папке и имени, а не нейросетью по содержимому
движения. Для файлов с непонятными именами надёжнее сразу использовать Punch/Kick.
Модель скачивается With Skin, отдельные анимации — Without Skin.

## 2. Проверить каталог

Меню Unity: **Tools → Fight Dataset → Generator → 1 Refresh Animation Catalog**.
Каталог находится в `Assets/Config/AnimationCatalog.asset`.

Неизвестные или невалидные клипы не используются молча. В каталоге можно отключить
клип, выбрать Kind + Manual Classification, ограничить скорость, задать нужную
реакцию через её Key, либо переопределить время контакта, атакующую кость и цель.
Ручные настройки сохраняются при обновлении каталога.

Для запуска нужен хотя бы один валидный Humanoid-персонаж и один Idle. Для ударов
также нужна атака и подходящая реакция. Недостающие категории будут указаны в отчёте.

## 3. Настроить генерацию

Версия от 10 ноября: сначала из исходного движения выделяется основная ударная
фаза и направление. Попадания во время подъёма рук из idle и позднего возврата
не запускают реакцию. Проверяются ладонь/проксимальные костяшки, а не один
вытянутый кончик пальца; для пинков — поверхность стопы. Удары проверяются по поверхности выбранной области тела в
реальной смешанной позе на выходном кадре. Касание защитной руки вместо головы
или корпуса не засчитывается. Основная ударная конечность должна двигаться к цели,
а не возвращаться из замаха. Допуск по умолчанию — 8 мм. Неподходящий клип/поза
отбраковывается; генератор выбирает совместимую атаку. Боковые движения плавно
направляются на второго персонажа через поворот при проигрывании. Реакция
смешивается с нулевым весом в кадре попадания и должна стать видимой за следующие
1–2 выходных кадра; пустое начало реакционного клипа обрезается автоматически.
Для головы и корпуса подбираются соответствующие доступные реакции.
Блоки и уклонения не включаются в контактные hit/kick/fight.

**Generator → Select Generator Config** открывает настройки в Inspector:

- Scenarios Per Category — число сценариев **на каждую включённую и доступную
  категорию**. `100` при включённых Hit и Kick = 100 ударов руками + 100 пинков.
  При Camera Views = 1 это 200 MP4; при трёх видах — 600 MP4. Если также включить
  Fight/Normal, каждая из этих категорий получит ещё по 100 сценариев;
- Camera Views — 1–3 отдельных синхронных ракурса;
- Камеры каждого сценария теперь независимы: уровень глаз, низкая, высокая,
  сверху вниз, через плечо и дальний план. Высота, азимут, дистанция, FOV и
  заполнение кадра меняются непрерывно; ракурсы одного сценария разнесены.
  Близкие планы сохраняют обоих персонажей целиком. Внутри MP4 камера статична.
- Вероятности ракурсов: высокая — 45%, сверху вниз — 15%, высокий общий план —
  15%, уровень глаз — 15%, через плечо — 5%, снизу — 5%. Итого примерно 75%
  верхних видов. Поля Camera Probabilities меняют относительные веса; на маленьком
  батче доли могут отличаться. Camera Views = 1 подходит для одного случайного
  ракурса на ролик; при 2–3 видах веса применяются к каждому виду независимо.
- Width, Height, FPS — по умолчанию 1280×720, 20 FPS;
- Seed — воспроизводимый выбор персонажей, анимаций и параметров;
- Minimum Duration Seconds — минимум длительности; fight удлиняется до конца обмена;
- Generate Hit/Kick/Fight/Normal — нужные категории;
- Speed Range — диапазон скорости, по умолчанию 0,8–1,2×;
- Среди совместимых атак приоритет получают реже использованные в этом батче.
  Случайный порядок сохраняется при одинаковом количестве использований.
  Неудачные варианты не увеличивают счётчик готовых ударов. После продолжения
  батча счётчики восстанавливаются. Равное число всех файлов не гарантируется:
  несовместимые движения не должны попадать в датасет ради статистики.
- Idle у персонажей идёт с независимыми фазами и темпом; время до удара, паузы,
  плавность переходов и скорость реакции немного различаются. Это использует
  имеющиеся клипы; новых движений система не сочиняет.
- Attack Blend In, Reaction Blend In, Blend Out — плавность переходов;
- Output Directory — папка результатов вне Assets.
- Use Async GPU Readback — ускоренная передача кадров с GPU; включена по умолчанию.
  Для сравнения или диагностики её можно отключить, сохранив разрешение и FPS.

## 4. Получить видео

Сначала **Generator → Run Small Smoke Test**: один сценарий каждой доступной
категории, по два ракурса. Затем **3 Generate Configured Batch** для объёма из конфига.
Пакет сам выполняется в Unity без запросов к ИИ на каждый ролик или кадр.

После завершения рядом с manifest.json появляется **animation_usage.csv**:
имя клипа, число готовых ударов, число попыток и отказов. Подробные причины отказов
указаны в animation_selection внутри JSON каждого готового сценария. Ноль готовых
ударов означает, что клип не выбран либо не прошёл проверки; смотри число попыток.

При запуске автоматически открывается окно прогресса. Его также можно открыть через
**Tools → Fight Dataset → Generator → 0 Generation Progress**.

- Общая полоса показывает прогресс батча; вторая — кадры текущего сценария.
- **Пауза** замораживает текущий кадр. **Продолжить** возобновляет с него, пока Unity
  открыта и не было перезагрузки скриптов.
- **Сохранить и остановить** освобождает ресурсы и сохраняет батч для продолжения.
- После перезапуска Unity нажми **Продолжить** для последнего батча либо
  **Продолжить из папки…** и выбери нужную папку `batch_...` с `resume.json`.
- После остановки/перезапуска незавершённый сценарий записывается с начала;
  уже готовые видео сохраняются и не перезаписываются. Старые незавершённые попытки
  архивируются в `logs/interrupted/` с расширением `.interrupted`.
- **Открыть папку** показывает результаты, **Настройки** открывает конфиг.

Во время рендера Unity должна оставаться в Edit Mode. При компиляции, закрытии
редактора, запуске Play или обновлении каталога батч автоматически сохраняется и
останавливается. Продолжение использует сохранённые seed и настройки, даже если
текущий конфиг уже изменён. Если изменились использованные модели, анимации,
материалы или код генератора, продолжение потребует вернуть исходники либо начать
новый пакет. Поддержка восстановления есть у новых батчей с `resume.json`;
ранее созданные пакеты остаются обычными готовыми результатами.

Результаты: `DatasetOutput/Generated/batch_.../`. Внутри — категории с MP4,
`metadata/` с JSON и `manifest.json` со списком файлов, split-группами и ошибками.
Все ракурсы и близкие seed-вариации одной семьи данных попадают в один split.

**2 Build Or Open Generator Room** открывает отдельную комнату для предварительного
просмотра. Пакет каждый раз строится из текущего конфига и каталога, независимо от
старой сохранённой тестовой сцены.

## Что ещё требует проверки

Refresh Animation Catalog применяет правила Root Motion также к старым FBX:
перенос и поворот сохраняются в позе. Иначе при покадровом воспроизведении
персонаж может терять выпад и выглядеть так, будто ноги остаются у стартовой точки.
Старые ролики с этим дефектом нужно записать заново. Проверенный пример с тем же
Punch_7 находится в `DatasetOutput/Checks/RootMotion_20261111/reported_export`.

Для клипов, заканчивающихся в новой точке, генератор сохраняет эту позицию при
переходе в Idle. Это исправляет обратное скольжение у kick_6, kick_7, kick_9,
kick_15 и kick_17. Смещение рассчитывается по самой анимации и учитывается в
следующих действиях, поэтому оно работает и для новых клипов. Полный список
проверки: `DatasetOutput/Checks/RootMotion_20261111/all_animation_fixes.csv`.

Генератор также проверяет проникновение поверхностей обоих персонажей друг в друга
на каждом выходном кадре: в подготовке, ударе, реакции и возврате в Idle. Вариант с
обнаруженным проникновением глубже 2 см отклоняется с причиной в `animation_selection`;
при записи проверка повторяется. Это проверка выборки точек реальных деформированных
мешей, поэтому ручной просмотр небольшого пакета всё ещё нужен. Обычный Collider
не остановит кости, которые задаются покадровым воспроизведением анимации.
Подбор дистанции начинает сближение из раздельного положения до касания поверхности.

Новые удары стоит сначала посмотреть в небольшом пакете. Геометрический контакт
проверяется до записи и повторно в кадре удара; физическая симуляция столкновения
не выполняется. Используй клипы с одним ударом, без комбо. Новая логика действует
в новых батчах; ранее записанные видео нужно пересоздать. Сохранённые незавершённые
батчи старой версии не продолжаются через изменившийся код генератора.
Падения/GetUp распознаются, но не включаются автоматически без проверки переходов
и пола. Пока из нейтральных анимаций есть только Idle, normal означает спокойное
стояние. Без реальных Kick, Block и Dodge эти возможности нельзя визуально проверить.

Опциональный Export Projected Body Joints сохраняет проекции костей, а не готовую
YOLO-разметку: недоступные точки лица и неизвестная видимость помечаются явно.
В новых батчах **Export Yolo Pose** сохраняет каждый кадр JPG и готовый TXT:
`yolo/images/{train,val,test}` и `yolo/labels/{train,val,test}`; конфигурация обучения
лежит в `yolo/data.yaml`. В TXT — два человека класса person, рамки и COCO 17
точек с видимостью 0/1/2. Генерация запускается прежней кнопкой
`3 Generate Configured Batch`. Старые видео нужно пересоздать для этой разметки.
Подробности и ограничения видимости — в разделе YOLO Pose в документации.
Трекинг, temporal classifier и обучение остаются отдельным последующим ML-этапом.

Технические детали и CLI-команды: `Docs/DatasetGenerator.md`.
