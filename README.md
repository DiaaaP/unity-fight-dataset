# Unity Fight Dataset

Локальный генератор синтетических сцен с двумя персонажами для подготовки
датасета взаимодействий и обучения YOLO Pose. Unity создаёт MP4, изображения
кадров, разметку COCO 17 и метаданные сценариев.

Это генератор данных. Обучение модели, трекинг и классификация действий во
времени выполняются отдельно.

## Требования и установка

- **Unity Editor 6000.0.85f1** через Unity Hub, Windows.
- **Git и Git LFS** для моделей и текстур.
- Пакеты Unity восстанавливаются из `Packages/manifest.json` и
  `Packages/packages-lock.json`; проект использует URP 17.0.4.
- Unity CLI и пакет Pipeline нужны для управления из терминала. Для запуска
  через меню редактора CLI не требуется.

```powershell
git clone --no-checkout https://github.com/DiaaaP/unity-fight-dataset.git
cd unity-fight-dataset
git lfs install --local
git restore --source=HEAD --worktree --staged -- .
git lfs pull
```

В Unity Hub выбери **Add → Add project from disk**, укажи папку клона и открой
проект нужной версией Editor. Дождись импорта и компиляции. Если FBX или PNG
оказываются короткими текстовыми файлами с `git-lfs.github.com/spec/v1`, выполни
`git lfs pull` перед повторным импортом.

Последовательность с `--no-checkout` также обходит обнаруженный на Git 2.45.1
сбой `active post-checkout hook found during git clone` при работе с Git LFS.
Она сохраняет защиту Git от запуска хуков во время клонирования.

В репозитории находятся код, сцены, настройки, FBX, текстуры и соответствующие
`.meta`. Кэш Unity, локальные инструменты, резервные копии и готовые датасеты
не входят в Git и создаются на компьютере пользователя.

## Быстрый запуск

1. Открой **Tools → Fight Dataset → Generator → 1 Refresh Animation Catalog**.
2. Выбери **Generator → Select Generator Config**.
3. Для первой проверки поставь **Scenarios Per Category = 1**,
   **Camera Views = 1**, включи **Generate Hit**, **Generate Kick** и
   **Export Yolo Pose**.
4. Нажми **Generator → 3 Generate Configured Batch**.
5. Следи за процессом в **Generator → 0 Generation Progress**. Editor должен
   оставаться открытым в Edit Mode.

Сохранённый конфиг проекта настроен на **100 сценариев на каждую категорию**,
Hit и Kick, один ракурс, **1280×720, 25 FPS**. Поэтому обычный запуск без
изменения настроек запрашивает **200 MP4**, а не 100.

При **Scenarios Per Category = 10**, Hit/Kick и одном ракурсе запрашиваются
**10 ударов руками + 10 пинков = 20 видео**. Camera Views умножает число MP4:
три синхронных ракурса тех же сценариев дадут 60 видео.

**Run Small Smoke Test** использует один сценарий на доступную категорию и два
ракурса. **2 Build Or Open Generator Room** открывает сцену для предварительного
просмотра; экспорт создаёт отдельную временную сцену.

## Персонажи и анимации

| Содержимое | Папка |
| --- | --- |
| Humanoid-модели с кожей и текстурами | `Assets/Characters/` |
| Одиночные удары руками | `Assets/Animations/Attacks/Punch/` |
| Одиночные пинки | `Assets/Animations/Attacks/Kick/` |
| Idle и спокойные движения | `Assets/Animations/Neutral/` |
| Реакции на попадания | `Assets/Animations/Reactions/` |
| Входящие клипы с распознаваемыми именами | `Assets/Animations/Inbox/` |

Модели обычно импортируются **With Skin**, отдельные анимации — **Without Skin**.
Импортёр настраивает Humanoid; после добавления файлов обнови каталог.
Используй клипы с одним ударом. Категории определяются по папке/имени файла,
время и направление удара уточняются по движению. Неизвестные клипы требуют
классификации в `Assets/Config/AnimationCatalog.asset`.

Уже настроены два персонажа и набор атак/реакций. Каталог позволяет отключать
клипы, менять тип, ограничения скорости, конечность, цель и время контакта.
Падения включаются только после проверки и отметки Reviewed Fall. Block/Dodge
не используются в сценариях, которые должны содержать попадание.

## Что рандомизируется

- Персонажи, совместимые клипы, скорости, начальные позиции и ориентация.
- Плавные переходы, время начала удара и реакции, фаза и темп Idle.
- Положение камеры, азимут, высота, FOV и заполнение кадра.
- Шесть семейств ракурсов: высокая камера, сверху, высокий общий план, уровень
  глаз, через плечо и низкая камера. По сохранённым весам около 75% выборок
  относятся к верхним видам; в малом батче доли могут отличаться.

Внутри одного MP4 камера статична. Несколько видов снимают одну и ту же позу
в один момент. Перед записью проверяются контакт, реакция, границы комнаты и
проникновение геометрии. Неподходящие варианты отклоняются и учитываются в отчёте.

## Результаты

Каждый запуск создаёт новую папку:

```text
DatasetOutput/Generated/batch_<date>_<id>/
  hit/                   # MP4 ударов руками
  kick/                  # MP4 пинков
  fight/                 # если включены обмены ударами
  normal/                # если включены нейтральные сценарии
  metadata/              # JSON сцен, действий, камер и времён
  inspection/            # отдельные контрольные кадры
  yolo/
    data.yaml
    images/train/        # также val/ и test/
    labels/train/        # также val/ и test/
  config.json
  manifest.json
  resume.json
  animation_usage.csv
```

`manifest.json` содержит готовые сценарии, пропуски и причины ошибок. Запрос на
20 сценариев при одном отказе может дать 19 готовых видео: смотри фактические
счётчики. Файлы в `yolo/.pending` и `logs/interrupted` не являются готовым датасетом.

## YOLO Pose / COCO 17

На каждый кадр создаются JPG и одноимённый TXT. Одна строка TXT — один человек;
обычно строк две. Класс **0 = person**. Hit/Kick — категории сценария в JSON,
а не отдельные классы людей в pose-разметке.

```text
class_id cx cy width height x1 y1 v1 ... x17 y17 v17
```

В строке 56 чисел. Координаты нормализованы в `[0, 1]`, начало изображения
сверху слева. Порядок: нос, левый/правый глаз, левое/правое ухо, плечи, локти,
запястья, тазобедренные суставы, колени, голеностопы. Стороны анатомические.

| Видимость | Значение в TXT |
| --- | --- |
| `0` — точка вне кадра | `0.0 0.0 0` |
| `1` — точка перекрыта | Реальные проекции `x y 1` |
| `2` — точка видима | Реальные проекции `x y 2` |

Видимость оценивается лучами по реальным деформированным мешам, с учётом
другого персонажа, собственного тела и комнаты. Для суставов внутри кожи
используется допуск толщины соответствующей анатомической области.
Нос, глаза и уши привязаны к поверхности. Это геометрическая оценка;
новые модели требуют проверки наложения точек. Отдельного редактора ручных
профилей точек лица пока нет.

Все кадры и ракурсы одного семейства персонажей/исходных клипов направляются
в один split. В малом батче val/test могут быть пустыми. `data.yaml` содержит
`kpt_shape: [17, 3]`, COCO `flip_idx` и путь к датасету. После переноса готового
батча на другой компьютер исправь `path` в этом YAML.

## Пауза, продолжение и длительная генерация

- **Pause** сохраняет текущую позу и кадр в памяти. **Resume** продолжает его.
- **Save And Stop**, закрытие Editor или перекомпиляция сохраняют завершённые
  сценарии. При следующем Resume незавершённый сценарий начинается с нуля.
- Продолжение использует снимок настроек и проверяет исходные модели, анимации,
  материалы, код и версию Unity. После изменения источников нужен новый батч.
- Async GPU Readback используется при поддержке GPU. После ошибки получения
  кадра сценарий может быть пропущен, дальнейшая запись переходит на обычное
  считывание; причина сохраняется в manifest.

На время длительной записи настрой Windows так, чтобы компьютер не уходил в
автоматический сон. Автоматическая защита от сна в генератор пока не встроена.
В одном из локальных запусков сон занял 23,5 минуты и после пробуждения вызвал
таймаут GPU; это время не характеризует производительность обработки кадров.

## Проверки и текущие ограничения

- Локально проверен экспорт 20 видео: 10 Hit + 10 Kick, 2 638 пар JPG/TXT.
  Готовые файлы и диагностические отчёты остаются локально в DatasetOutput.
- На каждом кадре проверяются попадание/проникновение и формируется разметка.
  Скорость зависит от сложности мешей и числа отклонённых вариантов; ускорение
  требует отдельного профилирования.
- Сейчас JPG/TXT сохраняются на **каждый** кадр видео. Соседние кадры Idle
  практически одинаковы. Разреженный отбор изображений для pose-обучения пока
  не встроен; этот параметр нельзя считать независимым от FPS видео.
- Геометрический контакт и проверки не гарантируют реализм любого нового
  клипа. Начинай с небольшого батча и просматривай результат.
- Встроенные Editor-проверки находятся в `Assets/Editor/Dataset*Checks.cs`.
  Исторические отчёты в документации относятся к указанным там датам и настройкам.

## Управление через терминал

После установки Unity CLI и подключения Pipeline к открытому Editor:

```powershell
unity status --project-path . --format json
unity command script eval 'return Application.unityVersion;' --project-path . --format json
unity command script eval 'return DatasetBatchExporter.StartBatch();' --project-path . --format json
unity command script eval 'DatasetBatchExporter.Pause(); return DatasetBatchExporter.Status;' --project-path . --format json
unity command script eval 'DatasetBatchExporter.Resume(); return DatasetBatchExporter.Status;' --project-path . --format json
unity command script eval 'DatasetBatchExporter.SaveAndStop(); return DatasetBatchExporter.Status;' --project-path . --format json
```

Запуск выполняется локально, без AI-запросов на каждый кадр. Используй путь
именно к этому проекту, если одновременно открыто несколько Editor.
