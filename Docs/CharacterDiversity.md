# Разные персонажи, рост и неполный кадр — 2026-11-26

В `Assets/Characters/` добавлены 17 новых FBX. Их Humanoid и материалы проверяются
через Unity Editor. Встроенные текстуры извлечены в отдельные папки каждой модели,
материалы переведены на URP/Lit и привязаны именно к своей модели. Для повторной
подготовки есть `Tools → Fight Dataset → Generator → Prepare Character Materials`.
Команда пропускает уже настроенные материалы; каталог обновляется по окончании.

## Настройки

`Tools → Fight Dataset → Generator → Select Generator Config`:

| Поле | Сохранённое значение | Действие |
| --- | --- | --- |
| Randomize Character Height | On | Независимо выбирать рост двум людям |
| Character Height Meters | 1.65–1.95 | Высота видимого меша в исходной нейтральной позе, в метрах |
| Partial Framing Probability | 0.4 | Вероятность запроса ракурса с частично обрезанным телом |
| Minimum Partial Body Coverage | 0.45 | Минимальная доля проекции тела, остающаяся в кадре |
| Camera Distance Meters | 0.95–7.5 | Диапазон запрашиваемой дистанции до центра сцены; геометрически неподходящие близкие виды отклоняются |
| Camera Fov | 30–110 | Более широкий диапазон объектива |
| Camera Roll Degrees | -7…7 | Наклон горизонта |
| Occlusion View Probability | 0.05 | Примерно один намеренно перекрывающийся вид на 20, со случайным местом внутри блока |
| Pose Training Samples Per Second | 5 | Частота кандидатов в обучающую выборку, отдельно от FPS видео |
| Target Occluded Training Fraction | 0.05 | Доля реальных межперсональных перекрытий в выбранных кадрах |

Рост меняется равномерным Scale по X/Y/Z, затем персонаж ставится на пол.
Дистанция, основная фаза удара и цель вычисляются уже на этой паре, после
изменения масштаба. Проверки контакта и проникновения продолжают использовать
деформированные меши. Это не перенос старой дистанции между новыми моделями.
Несовместимые пары клипа и телосложения отклоняются; все анимации не обязаны
подходить любому сочетанию роста. Для проверки оставлен прежний допуск контакта.

Метаданные `actors[].standing_height_meters` содержат исходный стоячий рост.
Во время наклона/пинка текущий вертикальный размер тела может изменяться.
`actors[].scale` сохраняет фактический масштаб, а `model_asset` — выбранную модель.

## Частичное кадрирование

Камера сначала получает безопасный полный ракурс и затем подбирает смещение/
приближение, обрезающее тело сверху, снизу или сбоку. Проверяется движение на
всём интервале: оба человека остаются достаточно видимыми, их меши не пересекают
ближнюю/дальнюю плоскости камеры. Контакт должен оставаться внутри изображения.
В кадре может отсутствовать голова или стопа; отсутствие всего человека
не считается подходящим кадром для этого режима.

В JSON камеры сохраняются `allowsPartialBody`, `crop`, `minimumBodyCoverage`
и `framing=partial_top/bottom/left/right`. Ракурс статичен внутри ролика.
Для одних полных кадров задай Partial Framing Probability = 0; для проверки
обрезки — 1. В обычном режиме 0.4 не гарантирует ровно 40% готовых роликов:
проверки могут отклонять неудачные варианты.

YOLO рамки обрезаются по границам изображения. Сустав за кадром записывается
как `0.0 0.0 0`; сустав внутри кадра, закрытый телом/предметом, сохраняет реальные
координаты и `v=1`. Непосредственно видимая точка получает `v=2`.

## Камеры, перекрытия и отбор для обучения

Комната увеличена до 12×12 м, чтобы дальняя камера помещалась внутри стен.
Дистанция выбирается логарифмически между близкими и дальними видами; положение,
азимут, высота, наклон горизонта, смещение точки прицеливания и размер людей в
изображении варьируются отдельно. Полные виды могут быть общими, средними или
приближенными; обрезанные сохраняют минимум видимой части тела. Запрошенный
минимум дистанции — не обещание камеры в 95 см при любом движении: такие виды
по-прежнему должны пройти проверки границ и кадрирования.

Для намеренных перекрытий камера выбирает направление ближе к линии между
людьми, а проекции тел должны заметно перекрываться на большей части временного
интервала. Эти виды помечаются `occlusionChallenge=true`. В них точка контакта
должна оставаться внутри изображения, но может быть закрыта телом. Обычные
ракурсы сохраняют дополнительную проверку видимости контакта.

При записи каждый кадр получает измерение `other_person_occluded_body_points`
в JSON: число точек **тела** внутри кадра, которые луч закрыл именно мешем другого
персонажа. Самоперекрытие, закрывающая голову кепка и стены не считаются такими
кадрами. Индекс — `view * frame_count + frame`. Кадр считается сложным, когда
закрыты минимум две из 24 точек тела обоих персонажей (лицо сюда не входит).

По завершении батча `yolo/data.yaml` указывает на `train_images.txt`,
`val_images.txt`, `test_images.txt`. Это поддерживаемые YOLO списки изображений:
https://docs.ultralytics.com/datasets/pose/
Полные JPG/TXT сохраняются, а `data_all_frames.yaml` позволяет использовать все
кадры. В обучающий список сначала попадают кандидаты примерно 5 раз в секунду,
кадры возле контакта и реакции; почти неподвижные соседние позы прореживаются.
Окончательный отбор распределён между сценариями и сохраняет исходные splits.

При наличии достаточного числа сложных и обычных кандидатов выбираются **1 кадр
с перекрытием на 19 без него**, то есть ровно 5% в объединённой выборке без
дублирования картинок. Доля в отдельном split может отличаться. Моменты возле
удара имеют приоритет при отборе. Общее число выбранных изображений может быть
существенно меньше исходного; смотри `candidate_frames` и `selected_frames`.

Если в маленьком батче реальных перекрытий не хватает, генератор сохраняет
кандидатов и честно пишет `target_met=false` и объяснение в `selection.json`.
Он не выдумывает перекрытия, не меняет флаги видимости и не дублирует один кадр
для искусственного достижения процента. В том же отчёте есть `source_frames`,
`source_occluded_frames`, `selected_occluded_frames`, `actual_fraction` и полный
список выбранных изображений. Старые батчи без измерений перекрытий нужно
создать заново для такого отбора.

## Лицо и новые модели

У моделей с кепками, пышными причёсками или аксессуарами геометрический поиск
носа/глаз может ошибаться. Текущие привязки проверяются на рендерах лица и
сохраняются как пять индексов вершин в `Assets/Config/DatasetFaceLandmarks.json`.
Они следуют за скиннингом и масштабом. Изменение самой модели/её зависимостей
делает профиль устаревшим и требует проверки, а не молчаливого использования
старых индексов. Это геометрическая разметка; наличие профиля не превращает
её в независимую ручную оценку видимости всех пикселей.

Диагностический просмотр всех моделей:
`DatasetCharacterDiversityChecks.StartAudit()` через CLI. Он создаёт полный
рендер, крупное лицо, TXT и JSON-отчёт в
`DatasetOutput/Checks/CharacterDiversity_20261126/`. Не запускай проверку во время
активной генерации. Программный метод CalibrateFace принимает координаты пяти
точек в контрольном изображении лица 512×512. Интерактивного окна разметки нет.

Поле FPS видео и сохранение каждого исходного JPG связаны, как в предыдущей версии.
Обучающая выборка теперь прореживается отдельно. Это сокращает набор для обучения,
но не устраняет стоимость рендера, скиннинга и подбора удара на каждом кадре.
Существующие батчи не меняются; новые возможности действуют при новой генерации.
